# 운영체제 강의 노트: 프로세스 관리

## 1. 프로세스의 개념

프로세스는 실행 중인 프로그램이다. 디스크에 저장된 프로그램 파일과 달리 프로세스는 메모리에 적재되어 CPU 시간을 할당받는다. 메모리 공간은 코드, 데이터, 힙, 스택 영역으로 나뉜다. 코드 영역은 실행할 명령어를, 데이터 영역은 전역 변수를 담는다. 힙은 실행 중 동적으로 할당되고 스택은 함수 호출 정보를 저장한다.

## 2. 프로세스 상태

프로세스는 생성, 준비, 실행, 대기, 종료 상태를 오간다. 준비 상태의 프로세스는 CPU를 기다리고, 대기 상태의 프로세스는 입출력 같은 사건의 완료를 기다린다. 타이머 인터럽트가 발생하면 실행 중이던 프로세스는 준비 상태로 돌아간다.

운영체제는 프로세스마다 PCB(프로세스 제어 블록)를 유지한다. PCB에는 프로세스 번호, 상태, 프로그램 카운터, 레지스터 값, 스케줄링 정보, 메모리 정보가 들어 있다.

## 3. 문맥 교환

문맥 교환은 CPU가 다른 프로세스를 실행하도록 현재 상태를 PCB에 저장하고 다음 프로세스의 상태를 복원하는 과정이다. 문맥 교환 중에는 사용자 코드가 실행되지 않으므로 순수한 오버헤드가 된다. 캐시와 TLB의 효율도 일시적으로 떨어질 수 있다.

## 4. CPU 스케줄링

스케줄러는 준비 큐에서 다음에 실행할 프로세스를 고른다. 평가 기준에는 CPU 이용률, 처리량, 반환 시간, 대기 시간, 응답 시간이 있다.

- FCFS: 먼저 도착한 순서대로 실행한다. 긴 작업 뒤에 짧은 작업이 줄 서는 호위 효과가 생긴다.
- SJF: 실행 시간이 가장 짧은 작업을 먼저 실행한다. 평균 대기 시간은 최소지만 실행 시간을 미리 알기 어렵다.
- 라운드 로빈: 같은 크기의 시간 할당량을 돌아가며 준다. 할당량이 너무 작으면 문맥 교환 비용이 커진다.
- 우선순위 스케줄링: 우선순위가 높은 작업을 먼저 실행한다. 기아 현상은 에이징으로 완화한다.
- 다단계 피드백 큐: 여러 큐를 두고 프로세스의 행동에 따라 큐를 옮긴다.

## 5. 프로세스 간 통신

프로세스는 기본적으로 메모리가 격리되어 있어 통신하려면 운영체제의 도움이 필요하다. 공유 메모리는 같은 메모리 영역을 함께 사용해 빠르지만 동기화가 필요하다. 메시지 전달은 커널을 거쳐 데이터를 주고받아 구현이 단순하지만 상대적으로 느리다. 파이프와 소켓이 대표적인 메시지 전달 수단이다.

## 6. 동기화

여러 실행 흐름이 공유 자원에 동시에 접근해 결과가 달라지는 상황을 경쟁 상태라고 한다. 공유 자원에 접근하는 코드 구간은 임계 구역이다. 뮤텍스는 한 번에 하나의 소유자만 허용하고, 세마포어는 지정한 개수만큼 접근을 허용한다.

교착 상태는 상호 배제, 점유와 대기, 비선점, 순환 대기의 네 조건이 동시에 성립할 때 발생한다.
